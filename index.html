第1回: データモデルと3層スキーマ構造

データベースシステムの基礎。データ独立性を確保するための3層スキーマが重要。

スキーマ定義するものデータ独立性
外部スキーマユーザやアプリから見たデータの見え方（ビューなど）論理的データ独立性
概念スキーマデータベース全体の論理的構造（テーブル定義など）論理・物理の境界
内部スキーマ物理的な格納方法（ファイル構造、インデックスなど）物理的データ独立性

※論理的データ独立性: 概念スキーマが変わっても外部スキーマ(アプリ)に影響しない。
※物理的データ独立性: 内部スキーマが変わっても概念スキーマに影響しない。

データを「表」として扱い、制約によって整合性を保つ。

キーの種類説明
スーパーキー行を一意に識別できる属性の組（余分な属性を含んでもよい）
候補キー一意性と極小性を満たすスーパーキー（値はタプルごとに異なる）
主キー候補キーから選ばれた1つ。NOT NULL（実体整合性制約）
外部キー他の表の主キーを参照する。参照整合性制約を保つ

関係演算（表から表を作る演算）の基本。

演算名意味・特徴

第4〜6回: SQLと副問合せ

SQLの評価順序と副問合せの挙動の理解が必須。

【SQLの論理的評価順序】
FROM ➔ WHERE (行の絞り込み) ➔ GROUP BY ➔ HAVING (グループの絞り込み) ➔ SELECT ➔ ORDER BY
  • 相関副問合せ: 外側の問合せの行を1つ取得するたびに、内側の副問合せが再実行される。
  • EXISTS: 条件を満たす行が「存在するか」のみを判定。NOT EXISTSは「誰の上司にもなっていない」などの否定条件に強い。

第11〜12回: インデックスとクエリ最適化

インデックス特徴・得意な検索
B+木葉ノードにのみ実データへのポインタを持つ。葉同士が連結されており範囲検索やソートに強い。
ハッシュキーから格納位置を直接計算。等価検索に極めて強いが範囲検索には不向き。
クラスタ化索引索引順とデータの物理配置が近い。範囲検索で連続ページを読みやすい。
非クラスタ化索引索引順と物理配置が一致しない。大量行を読むとランダムI/Oが増加する。

【結合アルゴリズム】
方式特徴
Nested Loop Join外側1行ごとに内側を走査。外側が小さく、内側に索引がある場合に高速。大表同士は遅い。
Sort Merge Join両方をソートしてから照合。
Hash Join一方をメモリ上でハッシュ表にし照合。大容量の等結合に強い。

※選択演算の早期適用: 結合前に条件で絞り込むことで、中間結果のサイズを小さくする（最適化の基本）。
